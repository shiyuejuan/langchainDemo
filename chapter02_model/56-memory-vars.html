56 · 短期记忆：代码追踪，变量怎么变（无比喻）

你说比喻反而迷糊，那我们就只看代码和真实输出，把三个词对应到具体变量上。

一、三样东西，落地就是三个变量

# 第 1 个变量：cp，就是 Checkpointer 本身（一个会存东西的对象） cp = InMemorySaver() # 第 2 个变量：agent，把 cp 接进去 agent = create_agent(model=llm, tools=[], system_prompt=..., checkpointer=cp) # 第 3 个变量：CFG，里面的 "t1" 字符串就是 Thread ID CFG = {"configurable": {"thread_id": "t1"}} # State 不是单独定义的变量——它就是每次 invoke 返回的那个字典（里面有 messages）
课程名词代码里的对应
Stateinvoke 返回的那个字典，里面有 messages 列表（这就是“记忆载体”）
Checkpointer变量 cp（一个 InMemorySaver() 对象），它内部用 thread_id 当钥匙存 state
Thread ID字符串 "t1"，写在 CFG 里，是 cp 存/取的钥匙

二、第 1 次 invoke 后，cp 抽屉里到底存了啥（真实代码打开看）

r1 = agent.invoke({"messages":[{"role":"user","content":"我叫小明"}]}, config=CFG)
第1次返回 state: messages 条数 = 2 内容 = [('human','我叫小明'), ('ai','你好，小明！...')] >>> 打开 cp 里 thread_id=t1 的抽屉： 抽屉里的 messages 条数 = 2 内容 = [('human','我叫小明'), ('ai','你好，小明！...')]

看：第 1 次 invoke 结束后，cp 的 t1 抽屉里已经存了一份 和返回结果一模一样的 messages（2 条）。 这是真代码 cp.get_tuple(CFG) 打开抽屉读出来的，不是我编的。

cp.get_tuple(CFG) 读出的 .checkpoint["channel_values"] 就是“抽屉里那份 state 变量”。

三、第 2 次 invoke（同一个 t1）：state 怎么被续上的（看变量变化）

r2 = agent.invoke({"messages":[{"role":"user","content":"我叫什么"}]}, config=CFG)
第2次返回 state: messages 条数 = 4 内容 = [('human','我叫小明'), ('ai','你好，小明！...'), ('human','我叫什么'), ('ai','你叫小明。')]

第 2 次返回 4 条 = 抽屉里取回的旧 2 条 + 本次新增的 2 条（你问 + AI 答）。

这就是“记住了”的全部真相：第 2 次 invoke 时，框架用 CFG 里的 "t1" 去 cp 找到抽屉， 把里面的 2 条 messages 取出来铺回 state，再接着聊。没有这一步，就是空 state 重新开始。

四、拆掉它们，变量怎么变（同一份代码跑的）

操作第 2 次返回的 messages 条数原因（看变量）
三样齐全（有 cp + t1）4 条cp 的 t1 抽屉有旧 2 条，取回归并
不接 cp（无 Checkpointer）2 条每次 invoke 都是新建的空 state 字典，旧变量没地方存
有 cp 但不给 thread_id直接报错cp 拿不到钥匙，不知道往哪个抽屉存
无 checkpointer：第2次返回的 messages 条数 = 2（永远 2，每次从空 state 开始） 有 checkpointer 但不给 thread_id → 报错：Checkpointer requires ... thread_id

五、把这页浓缩成 4 行

cp = InMemorySaver() # 存 state 的盒子 CFG = {"configurable":{"thread_id":"t1"}} # 盒子上的钥匙编号 state = agent.invoke(input, config=CFG) # 返回的字典 = 当前记忆（含 messages） # 下次 invoke 用同一个 CFG → 框架用 "t1" 打开 cp 的抽屉 → 取出旧 messages 续上
📌 没有故事，只有变量：cp 是盒子，CFG["thread_id"] 是钥匙，state 是盒子里那张记着 messages 的纸。
📌 “记住”= 第 2 次 invoke 用同一把钥匙打开同一个盒子，把旧纸上的 messages 拿回来接着写。
📌 缺盒子（cp）→ 每次都是新纸；缺钥匙（thread_id）→ 盒子不知道存哪、直接报错。
