60 · context 的「增删改」实跑讲解

课程 1.2.2 第三种上下文 context（静态运行时）。全部结论由 60-context-crud-demo.py 实跑验证，不是猜的。

先定位：context 到底是什么（代码层面）

# 1) 用 @dataclass 定义"形状" @dataclass class AppContext: user_id: str env: str db_host: str # 2) 在 create_agent 里声明形状（只是类型提示 + 校验，不存数据） agent = create_agent(..., context_schema=AppContext) # 3) 每次 invoke 把【具体实例】塞进去（顶层参数，不是 config 里） CTX = AppContext(user_id="u-1001", env="test", db_host="db:5432") agent.invoke({...}, config=CFG, context=CTX) # 4) 工具里用"点属性"读取 @tool def my_tool(question: str, runtime: ToolRuntime) -> str: ctx = runtime.context return f"{ctx.user_id} / {ctx.env}" # 点属性，不是方括号

一句话：context 是你每次调用时手动传入的一个普通 Python 对象，框架只是把它原样交给工具，既不保存、也不帮你改。这是理解"增删改"的总纲。

增 ADD在 context 里加一个字段

context 是 @dataclass，"加字段"就是改定义 + 构造实例时提供。不需要动框架、不需要动工具（工具用 getattr 兼容新旧两种 schema 即可）。

# 在原来的 3 字段基础上，新增 region @dataclass class AppContextV2: user_id: str env: str db_host: str region: str # ← 新增字段 CTX2 = AppContextV2(user_id="u-1001", env="test", db_host="db:5432", region="cn-east")
实跑输出（工具读到新字段）： region='cn-east'
"增"的本质 = 在 dataclass 类里多写一个属性。框架只认你声明的 context_schema 类型，实例带什么值就传什么值。

删 DELETE去掉一个 context 值

context 不是数据库，没有"运行中途删一行"这种操作。它的"删"只有两层含义：

① 静态删除（推荐）

从 @dataclass 定义里删掉该字段，构造实例时不再提供。工具里用 getattr(ctx, "字段", 默认值) 读取，删了也不报错。

② 本次不传（运行时隐藏）

某次 invoke 省略 context= 参数 → 工具里 runtime.context 变成 None。工具必须先判空，否则 AttributeError。

@tool def show_ctx(question: str, runtime: ToolRuntime) -> str: ctx = runtime.context if ctx is None: # ← 不传时必须判空 return "【runtime.context 是 None】本次 invoke 没有传 context" return f"{ctx.user_id} / {ctx.env}"
实跑输出（本次 invoke 省略 context 参数）： 【runtime.context 是 None】本次 invoke 没有传 context

改 UPDATE改 context 的值

有两种"改法"，结果天差地别——这是本节课最该记住的点。

改法 A（推荐）：下一次 invoke 传入"改过的实例"

框架不会替你改 context。想换值，就自己构造一个新实例再传进去。跨 invoke 生效，干净、可控。

r1 = agent.invoke({...}, config=cfg, context=AppContext("u-1","test","db:5432")) r2 = agent.invoke({...}, config=cfg, context=AppContext("u-1","prod","db:5432")) # 换了实例
实跑输出： 第 1 次(env=test): user_id=u-1, env=test, db_host=db:5432 第 2 次(env=prod): user_id=u-1, env=prod, db_host=db:5432 ← env 变了

改法 B（能改，但不是"记忆"）：工具里直接改对象属性

dataclass 默认可变，工具里写 runtime.context.env = "MUTATED" 语法上能成功。但这只在这个 Python 对象上生效：如果你反复传同一个实例，下一轮能看到；一旦传入一个全新实例，改动立刻归零。框架从头到尾没碰过它。

shared = AppContext("u-1", "test", "db:5432") # 同一个可变实例 # a. 读 shared → env = test # b. 工具里改 shared → env 被改成 MUTATED # c. 再读 shared → env = MUTATED （同一对象，看得见） # d. 读【全新实例】 → env = test （框架没保存，归零）
实跑输出（关键证明）： a. 读(同一实例 shared): 当前 env = test b. 改(仍传 shared): 已把 env 改成 MUTATED c. 再读(仍传 shared): 当前 env = MUTATED ← 看见改动，但这是对象共享 d. 读(全新实例): 当前 env = test ← 改动消失，框架没存
改法 B 只适合"本次运行临时借用"，绝不能用它当"跨轮记忆"。真正的跨轮记忆请用 state（工具返回 Command(update={...}) 写回 + checkpointer 保存）——那是 54/55/59 课讲过的机制。

关键验证context 不被 checkpoint 记住

同一个 thread_id，第 1 次传了 context，第 2 次完全不传。如果框架"记住"了，第 2 次应读到旧值；结果是 None。

实跑输出（同一线程 t-remember）： 第 1 次(传了): user_id=u-9, env=test, db_host=db:5432 第 2 次(同线程·不传): 【runtime.context 是 None】本次 invoke 没有传 context
结论：context 不存在 checkpoint 的 channel_values 里。它每次都是"你传什么就是什么"，不随线程续命。对比 state——state 的自定义字段会进 channel_values 并被 checkpointer 留住（见 56/58 课）。

context 增删改 vs state 增删改（一句话对照）

维度context（静态运行时）state（动态运行时）
数据存在哪你每次 invoke 传入的临时对象checkpoint 的 channel_values
跨 invoke 是否保留否（不传就没，同线程也不记）是（同 thread_id 自动续）
"增"怎么做改 @dataclass 定义 + 提供新字段Command(update={"新键":值}) 写回
"删"怎么做从定义删字段 / 本次不传（变 None）一般不清空，或覆盖为新值
"改"怎么做下次传新实例；或工具改对象（仅本次对象有效）工具 Command(update={...}) 写回，被记住
典型用途工牌/环境变量：env、db_host、api 根地址对话中演变的数据：user_name、counter

三个避坑点

坑 1：不传 context 不报错，但读到 None。 工具第一句务必 if runtime.context is None: return ...，否则 ctx.user_id 直接 AttributeError 崩溃。
坑 2：context_schema 是可选的。 不声明也能用，但声明后框架会按类型校验你传入的实例；传错形状会报错。团队项目建议声明。
坑 3：别把 context 当记忆用。 工具里改 runtime.context.xxx 看起来"生效了"，但换实例/换线程立刻丢。要记忆，用 state。
