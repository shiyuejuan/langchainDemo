52 · 这段 invoke 调用块逐行精讲

这是 47 课 demo 的“开跑”指令。前面 8 站都在准备：定义工具、挂好三套存储。这一段才是把数据灌进去、让 agent 真正跑一遍。

① 先准备两个“随身物件”

CFG = {"configurable": {"thread_id": "t1"}} CTX = AppContext(user_id="u-1001", env="test", db_host="db-internal:5432")

CFG —— 运行配置（含线程身份证）

LangGraph 的 config 是一个固定结构的字典：必须包一层 "configurable"。 里面最关键的 thread_id="t1" 就是这次对话的身份证号。checkpointer 靠它把 state 存进 “标着 t1 的抽屉”——下次还用 t1 来 invoke，就能从抽屉里把历史读回来（45 课机制）。 换 t2 就是另一个全新对话，互不串台。

CTX —— 静态工牌实例

用 50 课讲的 @dataclass 造出一张工牌：写死了 user_id / env / db_host。 这是“运行前就定死、运行中立了不许改”的元数据，待会儿作为 context 顶层传进去。

② invoke 的输入：那本“第一页作业”

r1 = agent.invoke( { # ← 第 1 个位置参数：输入（必须匹配 state 结构） "messages": [{"role": "user", "content": "我是谁？我的偏好和环境是什么？"}], "user_name": "小明", # ① 自定义 state 键，随输入进来 }, config=CFG, # 抽屉号 t1 context=CTX, # ③ 工牌（顶层 kwargs！） )

第 1 个位置参数 = 输入字典，它的键必须和 state 结构对得上（因为 state_schema=MyState）：

键是什么进了哪
messages本轮用户的新一句话，格式 {role, content} 由 add_messages reducer 追加进 state 的聊天历史
user_name我们自定义的"白板"栏，值 "小明" 写进 state["user_name"]（覆盖式更新，因为没给 reducer）

⚠️ 为什么 user_name 放输入里、user_id 却放 CTX 里？
user_name 是动态的、随运行演变的（白板）→ 属于 state，跟着输入走； user_id/env/db_host 是静态的、运行前定死的（工牌）→ 属于 context，单独传。这就是 47 课三种上下文分工的直观体现。

③ config= vs context=：两个平行的“随身包”

🪤 头号坑复习：context 是顶层关键字参数，绝不能塞进 config！

错误写法：agent.invoke(input, config={**CFG, "context": CTX}) → 工具里 runtime.context=None → AttributeError。

正确写法如上：config=CFG（抽屉号）和 context=CTX（工牌）是 invoke 的两个并列的顶层参数，各走各的通道。框架内部把 context 通过 runtime.context 递给工具。

④ 按“下回车”之后发生了什么（运行时序）

# 伪时序：langgraph 在背后自动做 1. 读 config → 用 thread_id="t1" 问 checkpointer 要历史（第一次：空） 2. 把输入合并进 state：messages += [用户这句话]，user_name = "小明" 3. 进模型节点 → LLM 看 system_prompt，决定"该调 my_info 工具" 4. 进工具节点 → my_info(runtime) 跑：打印 ①state ②store ③context 三块 5. 工具返回汇总字符串 → 再回模型节点 → LLM 据此生成最终回答 6. checkpointer 把最终 state 存回"t1 的抽屉" 7. return 整份 state 字典 → 存到 r1

r1 是什么？ 是运行结束后整份 state 字典（含所有 messages）。 所以取最终回答要：r1["messages"][-1].content —— messages 列表最后一条是 AI 的最终答复。

⑤ 一句话总结这块

📌 invoke 三个参数各管一件事：
第 1 个（位置参数）= 这次输入内容（messages + 自定义 state 键）；
config= = 抽屉号（thread_id，决定记忆存哪取哪）；
context= = 工牌（静态元数据，顶层传，别塞 config）。
