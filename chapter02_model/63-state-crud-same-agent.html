第63讲 · 同一个 agent 内，state「某个属性」的增删改

文件：63-state-crud-same-agent.py（已实跑验证）｜ 对照：61 课 context 同一 agent 增删改

直接回答：同一个 agent 内，针对某个属性

操作state 某个属性说明
改值✅ 支持Command(update={"属性":值})，跨轮自动记住，且不影响其他属性
增（加新属性）❌ 不行schema 冻结；未声明的键被忽略，不进通道/不进 checkpoint
删（删属性）❌ 不行不能删通道；只能把值覆盖成空，通道定义仍在（由 schema 决定）

结论和 61 课 context 一模一样：同一 agent 内属性"增删"都不行（根本原因是 state_schema 在编译期冻结，通道定死）。唯一比 context 强的是——state 改完的值会被 checkpoint 记住，context 改完不记住。

实验 setup：一个 agent 对象，挂了 4 个工具

class S(MessagesState):          # 同一个 state_schema，声明了 3 条通道
    user_name: str = ""
    city: str = ""               # 第二个属性，演示「某个属性」独立改
    counter: int = 0

agent = create_agent(model=llm,
    tools=[set_name, set_city, add_field, clear_city],  # 4 个工具都在同一 agent
    system_prompt="根据用户要求调用对应工具...",
    state_schema=S, checkpointer=InMemorySaver())

# add_field 尝试写未声明的 vip；clear_city 把 city 覆盖成空

关键：所有工具都挂在同一个 agent 对象上，且共享同一个 state_schema S。下面三个实验只是用不同 thread_id 触发不同工具。

① 同一 agent 内【改某个属性的值】—— 且记住、且多属性独立

# 同一 thread t1，先改 user_name，再改 city（中间没再调 set_name）
r1 = run("t1", "调用 set_name 工具")   # user_name=明明
r2 = run("t1", "调用 set_city 工具")    # city=北京
实跑输出： 调 set_name 后: user_name= '明明' | city= '<未写入>' 再调 set_city 后: user_name= '明明' | city= '北京' ← user_name 仍是明明(记住)，city=北京(新改)，两属性独立 checkpoint 里两条通道都在: True 和 True

三点铁证：① 改值成功（city 从空变北京）；② 跨轮记住（第2次 invoke 没调 set_name，但 user_name 还是明明）；③ 多属性互不干扰（改 city 没把 user_name 冲掉）。这是 context 做不到的——context 第2次不传就变 None。

② 同一 agent 内【增】一个未声明的属性 —— 被忽略

@tool
def add_field(q, runtime):
    return Command(update={
        "messages": [ToolMessage(..., tool_call_id=runtime.tool_call_id)],
        "vip": "yes",     # ← 未在 class S 声明
    })
实跑输出： 返回值里有 vip 吗: False checkpoint channel_values 键: ['messages', '__pregel_tasks'] → vip 既不在返回值也不在 checkpoint（写了等于白写）

注：上面 channel_values 只有 messages 和内部用的 __pregel_tasks，是因为 t2 线程只调了 add_field（写 vip 被忽略），从未写过 city/user_name；写过之后自定义字段会出现在 channel_values（56/58 课已证）。结论只针对"未声明键"：被忽略。

想要"多一个属性"，只能在 class S 里加一行（设计期），然后重建 agent——那就不是"运行时同一 agent 增属性"了。

③ 同一 agent 内【删】某个属性 —— 只能覆盖值，不能删通道

@tool
def clear_city(q, runtime):
    return Command(update={
        "messages": [ToolMessage(..., tool_call_id=runtime.tool_call_id)],
        "city": "",     # 覆盖成空，不是删除通道
    })
实跑输出： 先设 city: '北京' 再 clear_city 后 city= '' 通道 city 还在吗: True ← 删的是"值"，通道定义还在（由 schema 决定）

想真正"删掉 city 这个属性"？运行时做不到：runtime.state 是只读快照不能 del；唯一正道是改类定义删掉那行 + 重建 agent（设计期）。

④ 一张表看全：同一 agent 内，state 属性 vs context 属性

操作state 属性context 属性
改值✅ 记住 + 多属性独立✅ 但不记住（下次重传）
增属性❌ 未声明键被忽略❌ 不进 schema，换实例即消失（61）
删属性❌ 只能覆盖值，通道不消失⚠️ 别 del 已声明字段，会崩（61）
根因两者 schema 都在编译期冻结：state 字段=通道、context 字段=对象属性，运行时都不能增删
唯一差别值进 checkpoint，跨轮记住值不进 checkpoint，不记住

小结

  • 同一个 agent 内，state 某个属性：改值✅、增❌、删❌。增删被"schema 冻结"挡住，和 context 同一道墙。
  • state 比 context 强在改完会被记住：同一 thread_id 下次 invoke 还能读到，且多个属性各自独立互不冲掉。
  • 真要"加/删一个属性"只能改类定义 + 重建 agent（设计期），这不算"运行时同一 agent 增删"。
  • 需要运行时动态键值 + 跨会话长期记住 → 那是 store 的活儿（put/get/delete，47/48/49 课），state/context 都不擅长。
