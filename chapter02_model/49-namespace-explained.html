49 · namespace 人话版：它就是"文件夹路径"

一句话：namespace 就是你给档案柜里每份文件写的"存放地址"——一个多级文件夹路径。 元组的每一项就是路径的一级。

把 ("users", "xiaoming") 翻译成文件夹

档案柜（store）
└── users/ ← 元组第 1 项：一级文件夹（放"实体类型"）
    ├── xiaoming/ ← 元组第 2 项：二级文件夹（具体是谁）
    │   └── preferences ← key：文件名
    │       内容：{"language":"中文", ...} ← value：文件内容
    └── xiaohong/
       └── preferences
└── teams/ ← 换一类实体，另起一级
    └── alpha/
       └── reports/
          └── q3

所以 put(("users","xiaoming"), "preferences", {...}) 读出来就是一句人话： "把这份偏好存到 users 文件夹下 xiaoming 子文件夹里，文件名叫 preferences。"

"元组长度自由"是什么意思？（10 秒实验已证）

路径想分几级就分几级，1 级、2 级、3 级都能存能取：

s.put(('users',), 'counter', {'n': 1}) # 1 级路径 s.put(('users','xiaoming'), 'prefs', {'lang':'中文'}) # 2 级 s.put(('teams','alpha','reports'), 'q3', {'rev':'ok'}) # 3 级 # 三个全部 put/get 成功 ✓

分几级由你的业务定：只分用户 → 2 级够；多租户系统 → ("租户A", "users", "u1") 3 级；全局配置 → 1 级。

为什么要"前缀查询"？（这是元组最值钱的功能）

因为 namespace 是分级的，search 可以只给路径前几级，把这一片全捞出来——像 ls 一个目录：

你写人话实验结果
search(("users",))users/ 这个一级文件夹下所有子文件夹的所有文件捞到 ('users',)counter 和 ('users','xiaoming')prefs 两条 ✓
search(("users","xiaoming"))只看 xiaoming/ 这个子文件夹只捞到他的 prefs ✓
get(("users","xiaoming"), "prefs")精确打开某个文件返回 Item，数据在 .value ✓

常见疑问：为什么不直接用一个字符串当 key，比如 "users_xiaoming_prefs"？
因为字符串没法"按前半截查"。拆成元组后，框架才知道路径的层级结构， search(("users",)) 才能一键捞出全部用户的数据。扁平字符串做不到这件事——这就是"用元组而不用字符串"的全部理由。

记忆锚点

📌 namespace = 文件夹路径（元组，每项一级，级数自由）
📌 key = 文件名，value(dict) = 文件内容
📌 get = 精确打开；search(前缀元组) = ls 整个文件夹
