第09章开篇：上下文与记忆

第 15 讲 · agent 从"金鱼脑"到"有记性" · checkpointer + thread_id 入门

① 两个词先分清

概念是什么类比
上下文（context）每次调模型时发出去的内容：消息历史 + 系统提示 + 工具定义考试时摊在桌上的资料
记忆（memory）跨调用保留的内容：state 里的消息历史存在哪、存多久笔记本/草稿纸
短期记忆checkpointer 按 thread_id 存取 state → 多轮对话的"记性"一 conversations 一个本子
长期记忆store，跨 thread 共享（本章后面讲）公共档案柜
和已学内容的衔接：28 课 ContextEditingMiddleware 是"发送前修剪上下文"（省 token 不删历史）； 本章的 checkpointer 才是"历史从哪来"的答案——先有记忆，才谈得上修剪。

② 记忆怎么流转：invoke + checkpointer 全流程

③ 实跑铁证：消息条数一眼看穿

# ① 无 checkpointer：两次 invoke 各自独立
第1次（2 条消息）：你好，小明！…我已记住你的名字啦
第2次（2 条消息）：我不知道你的名字…        ← 金鱼脑！

# ② InMemorySaver + thread_id="xiaoming"
第1次（2 条消息）：你好，小明！…
第2次（4 条消息）：你叫小明呀！我之前就记住啦  ← 历史续上了！

# ③ 同一 checkpointer 换 thread_id="hacker"
新线程（2 条消息）：我不知道你的名字…        ← 线程隔离，不串台
读法：消息条数 = state 里积累了多少历史。②里第二次变 4 条（第1次的 H+A + 第2次的 H+A）， 说明 checkpointer 把第1次的 state 存下来、第2次 invoke 读回来续上了。 ①和③永远只有 2 条，说明历史压根没被保存。 
# 核心就两行：
agent = create_agent(model, tools, checkpointer=InMemorySaver())
agent.invoke({"messages": [...]}, {"configurable": {"thread_id": "xiaoming"}})
