wrap_model_call / wrap_tool_call 的「类方式」实现

第 13 讲 · 对应 40 课的函数装饰器方式 · 类方式的独有优势：有 self，能持有状态

① 类方式骨架（三条固定规则回顾）

class XxxMW(AgentMiddleware):      # 规则1：必须继承 AgentMiddleware
    def __init__(self):
        super().__init__()
        self.xxx = 0                    # 类方式独有：self 持有跨调用状态

    @property
    def name(self):                    # 规则2：name 是只读 property，别用 self.name= 存状态
        return "XxxMW"                # 不重写→默认=类名；同类多实例必须唯一（35 课坑）

    def wrap_model_call(self, request, handler):   # 必须叫这名（规则3：拼错静默失效）
        # request=模型请求, handler=洋葱下一层钥匙
        return handler(request)        # 放行 / override 改写 / 不调则短路

    def wrap_tool_call(self, request, handler):
        return handler(request)
类方式 vs 函数方式：函数方式 @wrap_model_call 本质就是 “自动帮你生成一个 AgentMiddleware 子类”（这正是 38 课规则1能成立的原因）。 二选一即可；需要 self 状态、多个钩子共享、或打包成可复用组件时用类方式，单行轻量用函数方式。

② 三种玩法（类方式重写 40 课）

# 玩法① 放行：log 后原样调用（用 self 计数，类方式独有）
class PassMW(AgentMiddleware):
    def __init__(self):
        super().__init__(); self.model_calls = 0
    @property
    def name(self): return "PassMW"
    def wrap_model_call(self, request, handler):
        self.model_calls += 1
        print(f"第 {self.model_calls} 次调模型")
        return handler(request)          # 原样放行

# 玩法② 改写：注入硬性指令（override system_message）
class InjectMW(AgentMiddleware):
    @property
    def name(self): return "InjectMW"
    def wrap_model_call(self, request, handler):
        extra = "\n[附加指令] 回答结尾必须带【完毕】"
        new_sys = _append_sys(request.system_message, extra)
        return handler(request.override(system_message=new_sys))

# 玩法③ 短路：不调 handler，自己造 ToolMessage
class FakeToolMW(AgentMiddleware):
    @property
    def name(self): return "FakeToolMW"
    def wrap_tool_call(self, request, handler):
        tc = request.tool_call            # ⚠️ 是「字典」不是对象！
        return [ToolMessage(content="（模拟）北京：晴 22 度",
                            tool_call_id=tc["id"])]

③ 实跑输出

# 玩法① 放行（self 计数跨 2 轮累加）
  [类·放行] 第 1 次调模型，记日志后原样放行
  [类·放行] 第 2 次调模型，记日志后原样放行
最终回答： 北京现在是晴天，气温 22 度…

# 玩法② 改写（注入【完毕】生效）
  [类·改写] 给模型注入硬性指令后放行
最终回答： 你好！有什么可以帮你的吗？【完毕】

# 玩法③ 短路（真工具被拦，没执行）
  [类·短路] 拦截工具 get_weather，不执行真工具，自己造假结果
最终回答： 北京现在是晴天，气温 22 度…
踩坑（实测）：wrap_tool_call 的 request.tool_call 在 LangChain 1.x 是字典——取名字用 tc["name"]、取 id 用 tc["id"]； 而 wrap_model_call 的 request 是带属性访问的对象（request.messages / request.system_message）。两者不一样，混用会 AttributeError。

④ 类方式 vs 函数方式 对照

维度类方式（本课）函数方式（40 课）
写法class Xxx(AgentMiddleware) 里写方法@wrap_model_call 直接装饰函数
持有状态✅ self 可跨调用存数据（计数/缓存）❌ 函数无 state（需闭包/全局）
多钩子打包✅ 一个类里可同时放 before/after/wrap多个装饰器，各自独立
name 判重需重写 name property 保证唯一函数名天然唯一，免坑
适用复用组件、带状态、多钩子共享单行轻量、一次性逻辑
一句话：函数方式是“语法糖”，背后就是动态生成你这个类。会写类方式，函数方式一看就懂； 会写函数方式，类方式只是把同一个函数搬进 AgentMiddleware 子类的方法里。
