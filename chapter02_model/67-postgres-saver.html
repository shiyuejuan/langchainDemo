67 · PostgresSaver：把对话存进 PostgreSQL

接 66 课（SqliteSaver）。本课把 checkpointer 后端从 SQLite 换成 PostgreSQL，证明"换一个后端只改一行代码"。全部实跑验证。

一、为什么学这一课

66 课我们用 SqliteSaver 把短期记忆落进单文件 SQLite，进程重启也不丢。但 SQLite 单文件在高并发下会锁库。生产环境常用 PostgreSQL 做 checkpointer——并发强、可多机共享。本课目标：把 66 课的 demo 换成 Postgres 后端，看"改了多少"。

State(白板)→ Checkpointer 留住→ PostgreSQL(磁盘·可并发)← thread_id 钥匙

66 课是"短期记忆落单文件"，本课是"短期记忆落数据库"——职责一样，只是后备从 SQLite 升到 PostgreSQL。

二、环境准备（本课已为你装好）

组件做法结果
PostgreSQL 服务下载 EDB 官方二进制 16.4 → initdb → pg_ctl 启动（端口 5432）已跑在 localhost:5432
库 + 角色建 langchain 库，owner=langchain/密码langchain已建好
Python 包pip install langgraph-checkpoint-postgres（含 psycopg 3）3.2.0 已装

坑记录：psycopg 3 需要 libpq 客户端库，装 psycopg-binary 自带 libpq 即可，不用动系统库（强行给 DYLD_LIBRARY_PATH 塞整个 pg/lib 会和系统 libiconv 冲突，macOS 经典坑）。

三、和 66 课（SqliteSaver）的唯一区别：一行

SQLite 版(66):  with SqliteSaver.from_conn_string("checkpoints.sqlite") as saver:
Postgres 版(67): with PostgresSaver.from_conn_string(
                      "postgresql://langchain:langchain@localhost:5432/langchain") as saver:
                      saver.setup()   # ← Postgres 多这一步：首次建表（幂等）

state、自定义字段 counter、工具 bump、系统提示、thread_id —— 全部一字未改。因为 SqliteSaver 和 PostgresSaver 都是 BaseCheckpointSaver 的子类，接口完全一致。

注意 Postgres 版本多一个 saver.setup()：首次必须建表（创建 checkpoints/checkpoint_writes/checkpoint_blobs/checkpoint_migrations 四张表），幂等，之后调用会跳过。

四、实跑输出（进程重启后记忆还在）

阶段一: thread=t1 连问 3 次 → counter = 1 → 2 → 3 阶段二(模拟重启: 全新 saver2 + 全新 agent2, 打开同一 PostgreSQL 库): 重启后未做任何 invoke, 直接读 t1 → counter = 3 第 4 次 invoke 后 → counter = 4 ← 从 3 接着到 4，记忆没丢

对照组（和 66 课同逻辑）：如果换成全新 InMemorySaver 读同一线程，会是 None——因为内存里啥都没有；而 Postgres 里数据一直在。

五、直接看 PostgreSQL 里的真实表

\dt Schema | Name | Type | Owner --------+-----------------------+-------+----------- public | checkpoint_blobs | table | langchain public | checkpoint_migrations | table | langchain public | checkpoint_writes | table | langchain public | checkpoints | table | langchain SELECT thread_id, count(*) FROM checkpoints GROUP BY thread_id; thread_id | rows -----------+------ t1 | 20

四张表就是 langgraph 存短期记忆的地方；t1 线程 20 条记录（和 66 课 SQLite 里数量一致，证明结构相同只是换了发动机）。

六、关键对比

Checkpointer后端适用进程重启并发
InMemorySaver内存 RAM临时/演示全丢仅单进程
SqliteSaver(66)单文件 .sqlite单机小项目不丢易锁库
PostgresSaver(本课)PostgreSQL生产/高并发不丢强

三者都是 BaseCheckpointSaver，切换只改构造那一行 + Postgres 多一个 setup()。这就是 langgraph 把"存哪"和"怎么跑"解耦的好处。

一个区分：checkpointer（含 Postgres）解决的是"同一线程的短期历史别因重启/多机而丢"；而"跨所有会话长期记住某人偏好"是 store 的活儿（47/65 课）。两者常配合：checkpointer 记对话、store 记长期档案。

七、一句话总结

把 66 课的 SqliteSaver 换成 PostgresSaver，只有一行 URI 变了，业务逻辑完全复用，记忆照样落盘、重启续命。生产里选 Postgres 是因为它扛并发、可多机共享——这就是"短期记忆持久化"从玩具到生产的那一步。
