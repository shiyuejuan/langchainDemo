55 · 短期记忆三脚凳：State + Checkpointer + Thread ID（缺一即塌）

课程公式：短期记忆 = State（会话内部状态）＋ Checkpointer（持久化机制）＋ Thread ID（会话作用域）。 这三块咱们分别在 45/47/52 课摸过，但“组合”的意义是：三条腿一条都不能少。 我做了“拆腿实验”——每次拆掉一条腿，看凳子怎么塌（55 demo 实跑）。

三脚凳比喻：哪条腿管什么

腿角色没有它会怎样
State凳面：本轮对话正在累积的消息和字段（白板）根本没有“内容”可记
Checkpointer存档员：每步结束把 state 拍照存档，下轮自动铺回凳面擦了就没了——金鱼脑
Thread ID抽屉号：决定存档存进哪个抽屉、下轮从哪个抽屉取存档员不知道往哪存/从哪取——报错或串台

拆腿实验实跑结果（4 组）

实验 0 三条腿齐全 第1轮 2 条 → 第2轮 4 条 回答：“你叫小测！” ← 记住了 ✓ 实验 1 拆 Checkpointer（state 和 thread_id 都在，但没人存档） 第1轮 2 条 → 第2轮 2 条 回答：“你还没告诉我你的名字” ← 金鱼脑 ✗ 实验 2 拆 Thread ID（有 checkpointer 但 config 不给线程号） 直接报错：Checkpointer requires ... 'thread_id' ← 存档员罢工 ✗ 实验 3 只给 Thread ID（agent 没接 checkpointer） 第1轮 2 条 → 第2轮 2 条 回答：“你还没告诉我你的名字” ← 身份证没处刷 ✗

逐个解读

实验 0（齐全）：第 2 轮消息 2→4 条——checkpointer 把第 1 轮的 state 拍照存进 t1 抽屉， 第 2 轮 invoke 自动铺回来接着聊，所以模型记得“小测”。

实验 1（无 Checkpointer）：state 照样存在（每次运行内部有消息列表），但运行结束就扔—— 第 2 轮从头开始，2 条消息，模型说“你还没告诉我名字”。这正是 45 课场景①的金鱼脑。

实验 2（无 Thread ID）：这条最“刚”——直接 ValueError：“Checkpointer requires ... thread_id”。 存档员上岗了，但你没给他抽屉号，他拒绝工作。这是框架的强制约束，防止你以为在续聊其实没存上。

实验 3（有 Thread ID 没 Checkpointer）：thread_id 只是 config 里一个字符串，没有存档员， 它啥也干不了——第 2 轮照样 2 条金鱼脑。身份证明没有抽屉系统配合，就是一张废纸。

一句话记住

📌 短期记忆是三件套，不是单件：State 是“记什么”，Checkpointer 是“怎么留住”，Thread ID 是“记在谁名下”。
📌 拆 Checkpointer → 金鱼脑；拆 Thread ID → 直接报错；只给 Thread ID → 废纸一张。
📌 三条腿都在，才叫“这个会话有记忆”。
