61 · 同一个 agent 里，context 到底能不能"增删改"

配套 61-context-crud-same-agent.py，全部结论实跑验证。一句话先给：同一 agent 内只能改"值"；加/删"字段"只是改了某个对象，schema 冻结、不持久，且 del 已声明字段会崩。

边界总览

操作同一 agent 内能否做真相
改值（env 从 test→prod）可以重传新实例即可，框架原样透传
增字段（schema 里加 region）不行schema 在 create_agent 时冻结；只能给"对象"硬加属性，不进 schema、不持久
删字段（schema 里去掉 db_host）不行不能运行时删定义；置空（=None）是安全做法；用 del 删已声明字段会崩

① 改值 ✅同一 agent，改字段的值

这是 context 唯一被"原生支持"的增删改动作。每次 invoke(context=新实例) 传入不同值，工具读到新值。schema 不变，只是内容变了。

# 同一个 agent、同一个 context_schema=AppContext ask("读取所有字段。", AppContext("u-1","test","db:5432")) ask("读取所有字段。", AppContext("u-1","prod","db:5432")) # 重传实例改值
env=test : user_id='u-1' | env='test' | db_host='db:5432' | region=不存在 env=prod : user_id='u-1' | env='prod' | db_host='db:5432' | region=不存在

② 增字段 ❌schema 冻结，加不了"定义的字段"

同一个 agent 的 context_schema 在 create_agent 那一刻就固定了。工具里你可以用 Python 动态给对象加一个属性（如 region），但：

能"硬加"（仅当前对象）

runtime.context.region = "cn-east" # schema 没这字段
加后(同对象): region='cn-east'

但换实例就消失（没进 schema、没被记住）

换全新实例: region=不存在

证明：加的是"那个 Python 对象"的属性，不是 schema 的一部分，框架不保存。

想让 agent 真正多一个字段，只能：改 AppContext 类定义 + 重建 create_agent（新 agent）。同一 agent 内做不到。

③ 删字段 ⚠️置空安全，del 危险

要"去掉"一个值，正确做法是置空；千万别用 Python 的 del 删已声明字段。

# 安全：置空（字段定义仍在 schema 里） runtime.context.db_host = None
删前(fresh): db_host='db:5432' 置空后 : db_host=None 换全新实例 : db_host='db:5432' ← 置空只作用于那个对象，schema 没变
危险：del runtime.context.db_host（删已声明字段）。本轮可能不报错，但下一个工具调用必崩——因为框架要把 context 重新注入下一个工具的 ToolRuntime，并按 AppContext schema 校验，发现 db_host 缺失就抛 AttributeError。崩溃发生在框架注入参数阶段（tool_node 内部），工具自身的 try/except 救不了。
del 之后(本轮没事): 已执行删除操作，db_host 字段已从对象上移除。 再调用工具 → 果然崩了: AttributeError : 'AppContext' object has no attribute 'db_host' 根因：框架把 context 重新注入下一个工具的 ToolRuntime 时，按 schema 校验发现字段缺失。

结论：context 不是数据库，动态增删键值该用 store

把职责分清楚

你想要的能力该用谁
一次传入、运行中只读的静态配置（env / db_host / api 根地址）context（@dataclass，点属性读；只能改值）
运行期动态增/删/查键值，且跨轮/跨会话记住store（InMemoryStore.put/get/search/delete，47/48/49 课讲过）
随对话演变且被 checkpoint 记住的状态state（Command(update={...})，54/55/59 课讲过）
一句话：同一 agent 内，context 只能"改值"；"增/删字段"是改某个对象、不进 schema、不持久，且 del 已声明字段会触发框架崩溃。真正需要动态增删键值并跨轮记住的，是 store，不是 context。
