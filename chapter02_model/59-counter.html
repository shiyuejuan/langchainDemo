59 · 案例②：按线程计数（和 user_name 不同的另一种短期记忆）

57/58 课讲了“存哪/存什么”。你点名要一个不存 user_name 的可跑案例——这就是： 同一个 thread_id 每次对话，state 里一个 counter 自动 +1，跨 invoke 持续累加。 和 user_name（每次靠输入传）不同，这是 state 里一个会自己增长的字段，靠 checkpointer 存住。

一、真实跑出来的结果（59-counter-demo.py）

===== 同一个 thread_id=t1，连问 3 次 ===== 第 1 次 invoke 后 → state.counter = 1 第 2 次 invoke 后 → state.counter = 2 第 3 次 invoke 后 → state.counter = 3 ===== 换个线程 thread_id=t2（全新记忆，从头开始） ===== t2 第 1 次 invoke 后 → state.counter = 1 （不是 4，而是 0+1） ===== 回到 t1（记忆还在，继续累加） ===== t1 第 4 次 invoke 后 → state.counter = 4 （接着 3 变成 4，证明 t1 记忆没丢）

看：同一线程 t1 累计 1→2→3→4；换 t2 立刻从 1 重来（隔离）；回到 t1 还能接着 3→4（记忆没丢）。 这就是“短期记忆 + 线程隔离”最直观的证据，而且数据不是 user_name，是一个动态累加的计数器。

二、关键代码（三处和 47 课不同）

# ① 自定义 state：在 messages 之外加一个 counter，初始 0 class MyState(MessagesState): counter: int = 0 # ② 工具：读当前 counter，+1，写回 state（核心机制） @tool def bump(question: str, runtime: ToolRuntime) -> Command: cur = runtime.state.get("counter", 0) return Command(update={ "messages": [ToolMessage(content=f"计数已更新为 {cur + 1}", tool_call_id=runtime.tool_call_id)], # 对账用的工具消息 "counter": cur + 1, # 写回 state 的 counter 字段 }) # ③ 组装时挂上 state_schema + checkpointer（和 47 课一样） agent = create_agent(..., state_schema=MyState, checkpointer=InMemorySaver())

三、这个案例新学到一个机制：工具怎么“写回 state”

47 课的 my_info 工具只是读 state（runtime.state.get(...)）。 本案例的工具要写 state——靠返回 langgraph.types.Command：

  • Command(update={通道名: 值})：按通道名写回。我们写了两个通道—— "counter" 写数字，"messages" 通道放一条 ToolMessage（框架要求工具调用必须对账，否则报“缺 ToolMessage”）；
  • 工具里用 runtime.tool_call_id 拿到本次工具调用的 id，填进 ToolMessage 完成对账。

这是 47 课没覆盖的“工具→写 state”正路子，短期记忆里凡是“要改、要累计”的数据都用它。

四、和 user_name 案例对照：同一个 checkpointer，两种用法

47 课 user_name本案例 counter
数据怎么进 state每次 invoke 的输入传进来工具运行时计算后写回
会自己变吗不会（你传啥就是啥）会（每次 +1 累加）
工具怎么用 state只读 get读 + Command 写回
共同前提都要 state_schema + checkpointer + 同一 thread_id 才能跨 invoke 存住
📌 一句话：短期记忆不只是“记个名字”，还能存任意会演变的数据（计数、积分、进度…）。 只要把它放进 state_schema，并用 checkpointer + thread_id 存住，工具就能量化地改它、跨对话累加。
📌 工具写回 state 的标准姿势：return Command(update={"通道名": 值, "messages":[ToolMessage(...)]})。
